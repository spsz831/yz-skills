# AI杨侦探工作流日常操作说明

这份说明只回答 3 个高频问题：

1. 我如果只想生成日报，怎么跑
2. 我如果想完整跑一整套流程，怎么跑
3. 我到底应该双击 `cmd`，还是直接在 Codex / Claude Code 里提需求

---

## 一、先记住这套项目的两种用法

这个项目有两层：

- 脚本层：负责跑日报、准备写作工作单、整理插图、定稿、发布包装
- agent + skill 层：负责选题判断、长文写作、发文态优化、插图规划与插图生成

所以你以后操作时，按下面这个简单原则：

- 只跑日报，优先用脚本
- 只想机械跑完整脚本链路，也优先用脚本
- 涉及“选题判断、写文章、改成公众号风格、配图风格控制”，优先在 Codex / Claude Code 里直接提需求

再补两条日常约定：

- 大部分 `.cmd` 入口都适合双击运行；双击时默认应该保留结果窗口，不应该一闪而过。
- 如果你在终端里批量跑脚本，优先使用脚本自带参数关闭暂停，例如 `--no-pause`。

## 二、场景 1：只想生成日报

这是最简单、最稳定的一种用法。

### 方式 A：双击启动器

直接运行：

```bat
scripts\ai-daily-digest-launcher.cmd
```

进入后按提示选择：

- 时间范围：建议 `48 小时`
- 文章数量：建议 `15`
- 语言：通常选 `中文`

适合：

- 日常看盘
- 不想记命令
- 只想先把日报跑出来

### 方式 B：命令行直接跑

在项目目录执行：

```powershell
npx -y bun scripts/digest.ts --hours 48 --top-n 15 --lang zh --output ./reports/output/ai-daily-digest-manual.md --health-log ./reports/health/run-manual.json
```

适合：

- 想固定参数
- 想自己控制输出文件名
- 想让 agent 直接执行一条明确命令

### 日报输出位置

- 日报文件：`reports/output/`
- 健康日志：`reports/health/`

默认你主要看的是：

- `reports/output/ai-daily-digest-*.md`

## 三、场景 2：先跑到正式写作关口

运行：

```bat
scripts\run-digest-gzhrb-publish-pipeline.cmd
```

这条链路现在会顺序执行：

1. 生成日报
2. 提取候选题
3. 人工确认选题
4. 创建双 skill 写作工作单
5. 停在正式写作关口

适合：

- 你想先把日报、选题和文章 ID 固定下来
- 你准备接着用 `khazix-writer` 和 `wechat-article-writer` 写作
- 你不想再让仓库内置生成器直接代写正文

### 输出位置

- 日报：`reports/output/`
- 初稿占位：`reports/gzhrb/drafts/`
- 写作工作单：`reports/gzhrb/workitems/`
- 人工确认：`reports/gzhrb/approvals/<article-id>/`
- 执行留痕：`reports/gzhrb/provenance/<article-id>/`
- 优化稿工作副本：`reports/gzhrb/articles/<article-id>/article.md`
- 插图目录：`reports/gzhrb/illustrations/<article-id>/`
- 最终发布单元：`reports/gzhrb/publish-units/<article-id>/`

补充：
- 如果已经过人工选题确认，`<article-id>` 会带题材 slug
- 目的就是避免同一份日报换题重跑时，把不同题材的插图混在同一个目录里

最终你主要会得到：

- 一份工作单 `workitems/gzhrb-*.json`
- 一个固定的 `khazix-writer` 初稿路径
- 一个固定的 `wechat-article-writer` 优化稿路径
- 一个固定的文章级插图目录

这里也要区分两件事：

- `按 skill 规范写`：agent 参考 skill 规范直接写稿
- `正式双 skill 留痕执行`：必须把 `khazix-writer` 初稿和 `wechat-article-writer` 优化稿分别写到工作单指定路径

当前项目的正式链路默认按第二种理解。因为后半段脚本现在会看真实文件，而不是只看口头说明。

## 四、场景 3：写作完成后，继续跑后半段

当 `khazix-writer` 初稿和 `wechat-article-writer` 优化稿已经完成，并且优化稿已经保存到工作副本路径后，再执行：

```bat
scripts\run-gzhrb-postwriting-pipeline.cmd "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md"
```

这条后半段链路会顺序执行：

1. 插图规划
2. 插图生成
3. 归档图片
4. 回填 Markdown
5. 发布包装

如果你还没写完正式双 skill 产物，这条命令现在会直接拦住，不会继续往下跑。它会根据工作单、文件证据、`provenance` 和 `approval` 判断当前处于哪一段：

- `awaiting_topic_approval`
- `awaiting_khazix_execution`
- `awaiting_khazix_approval`
- `awaiting_wechat_execution`
- `awaiting_wechat_approval`
- `awaiting_illustration_execution`
- `ready_for_publish_unit`
- `completed`

注意：

- `reports/gzhrb/drafts/*-khazix.md` 里的 `khazix-writer 初稿占位文件` 不算正式初稿
- 只有 `reports/gzhrb/articles/<article-id>/article.md` 真实存在且非空，且 `wechat provenance + approval` 齐备，后处理链路才会放行
- 如果你想用一个总入口统一做这几步，可以运行 `scripts\gzhrb-writing-state.cmd`
- 想看帮助可以运行 `scripts\gzhrb-writing-state.cmd help`
- 想拿 JSON 结果可以运行 `scripts\gzhrb-writing-state.cmd inspect-json --article "<article-path>"`
- 想按文件证据自动把显式状态补齐，可以运行 `scripts\gzhrb-writing-state.cmd auto-sync --article "<article-path>"`
- 想一次看最近几篇的状态概览，可以运行 `scripts\gzhrb-writing-state.cmd status-summary --limit 5`
- 想拿最近几篇状态的 JSON 结果，可以运行 `scripts\gzhrb-writing-state.cmd status-summary-json --limit 5`
- 如果你想把这一步明确记进工作单，可以在初稿完成后运行 `scripts\mark-gzhrb-khazix-complete.cmd`
- 优化稿落盘后，可以运行 `scripts\mark-gzhrb-wechat-complete.cmd`
- 每次正式 skill 执行完成后，还要运行 `scripts\write-gzhrb-provenance.cmd`
- 每个关口人工确认后，要运行 `scripts\gzhrb-writing-state.cmd approve-topic|approve-khazix|approve-wechat`
- 如果你不确定当前卡在哪，可以运行 `scripts\inspect-gzhrb-writing-state.cmd`
- `scripts\run-gzhrb-postwriting-pipeline.cmd` 现在会先自动 inspect 一次，再继续后半段

### 正式写作完成后，最短检查步骤

如果你不想每次重新想一遍，进入后半段前就按下面检查：

1. 先跑 `scripts\check-codex-required-skills.cmd`
2. 先做选题确认：`scripts\gzhrb-writing-state.cmd approve-topic --article "<article-path>"`
3. `khazix` 初稿落盘后，写 `khazix provenance`，再执行 `mark-khazix` 和 `approve-khazix`
4. `wechat` 优化稿落盘到 `articles/<article-id>/article.md` 后，写 `wechat provenance`，再执行 `mark-wechat` 和 `approve-wechat`
5. 跑 `scripts\gzhrb-writing-state.cmd inspect --article "<article-path>"`
6. 看到当前阶段至少已经进入 `awaiting_illustration_execution` 后，再跑 `scripts\run-gzhrb-postwriting-pipeline.cmd`

如果你想直接照抄命令，最短可以这样跑：

```bat
scripts\gzhrb-writing-state.cmd approve-topic --article "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md"

scripts\write-gzhrb-provenance.cmd -ArticlePath "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md" -SkillName "khazix-writer" -InputPath "E:\WorkCodex\ai-daily-digest\reports\output\ai-daily-digest-*.md" -OutputPath "E:\WorkCodex\ai-daily-digest\reports\gzhrb\drafts\<article-id>-khazix.md" -SessionId "codex-session-id"
scripts\gzhrb-writing-state.cmd mark-khazix --article "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md"
scripts\gzhrb-writing-state.cmd approve-khazix --article "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md"

scripts\write-gzhrb-provenance.cmd -ArticlePath "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md" -SkillName "wechat-article-writer" -InputPath "E:\WorkCodex\ai-daily-digest\reports\gzhrb\drafts\<article-id>-khazix.md" -OutputPath "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md" -SessionId "codex-session-id"
scripts\gzhrb-writing-state.cmd mark-wechat --article "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md"
scripts\gzhrb-writing-state.cmd approve-wechat --article "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md"
```

想看更短的日常执行卡，可以直接打开：

- [`docs/gzhrb-writing-checklist.md`](E:/WorkCodex/ai-daily-digest/docs/gzhrb-writing-checklist.md)

### 五个公众号后处理脚本分别是干嘛的

- `scripts\plan-gzhrb-illustrations.cmd`：生成插图规划、插图位、提示词和批处理配置。
- `scripts\generate-gzhrb-illustrations.cmd`：按规划批量生成插图素材。
- `scripts\organize-gzhrb-illustrations.cmd`：把图片、提示词、元数据归档到文章级目录。
- `scripts\finalize-gzhrb-article.cmd`：把图片路径回填到 `articles/<article-id>/article.md`，完成文章定稿。
- `scripts\package-gzhrb-article.cmd`：把标题备选、引导语备选、话题标签和插图复制进 `publish-units/<article-id>/`，形成最终发文单元。

## 五、场景 4：想按“AI杨侦探正式工作流”来做

推荐顺序是：

1. 先生成 `48 小时日报`
2. 从日报里挑当天最适合写长文的题
3. 人工确认选题
4. 用 `khazix-writer` 写长文初稿
5. 用 `wechat-article-writer` 做发文态优化，并默认产出标题备选
6. 用 `baoyu-article-illustrator` 连续完成插图规划和插图生成
7. 归档图片并回填到 Markdown
8. 补齐引导语、话题标签，形成最终发文包
9. 人工终审

补充约束：

- `wechat` 审批通过后，插图规划、插图生成、图片回填默认连续执行，不再额外等待人工确认
- 插图阶段对外统一描述为 `baoyu-article-illustrator`，不要再拆成其它独立 skill 或工具名

这个模式下，最适合直接在 Codex / Claude Code 里提需求。

补一条账号层默认约定：

- `wechat-article-writer` 发文态优化时，文章最上方应先明确交代“这条具体新闻是什么”，再进入分析判断
- 如果新闻有明确来源、计费数字、关键时间点，优先在开头第一屏交代清楚
- 默认在文末追加 AI杨侦探固定尾注，格式如下：

```md
---

<br/>

如果你觉得这篇内容有价值，欢迎点个赞、点个在看，也欢迎转发给更多朋友。

我是 `AI杨侦探`，持续记录 AI、技术、产品和产业变化里那些真正值得看、值得想的事。

谢谢你读到这里，我们下次见。
```

## 六、场景 5：想看日报抓取健康情况

运行：

```bat
scripts\analyze-ai-digest-health.cmd
```

这个脚本会：

1. 读取最近若干次 `reports\health\run-*.json`
2. 统计每个源的 `ok / empty / error`
3. 给出 `disable / observe / keep` 三类建议
4. 输出报告到 `reports\health\health-analysis-*.md`

如果你是在终端里跑，不想停住窗口，可以执行：

```bat
scripts\analyze-ai-digest-health.cmd --no-pause -Last 7
```

适合：

- 想看哪些源最近持续超时、403 或空结果
- 想复盘“今天日报为什么质量波动”
- 想决定哪些源值得继续观察

注意：

- 这个脚本当前只做分析报告，不会自动修改源配置。
- 报告是诊断建议，不是自动化变更动作。

## 七、到底什么时候用 cmd，什么时候直接找 agent

### 用 `cmd` / 命令行

适合下面这些事：

- 只跑日报
- 只跑固定脚本链路
- 不需要 agent 帮你做选题判断
- 不需要 agent 帮你写长文和控制文章风格

你可以理解成：

- `cmd` 更像“执行器”

### 用 Codex / Claude Code 直接提需求

适合下面这些事：

- 从日报里判断今天写哪条更合适
- 按 AI杨侦探账号风格写成长文
- 用最新版 `wechat-article-writer` 做公众号发文态优化
- 用 `baoyu-article-illustrator` 按既定风格做插图
- 希望一步步接着昨天的状态继续往下做

你可以理解成：

- agent 更像“总控编辑 + 工作流协调器”

补一条硬规则：

- 如果你准备在当前 Codex 窗口里进入正式双 skill 写作阶段，先执行 `scripts\check-codex-required-skills.cmd`
- 只有同时看到 `[OK] khazix-writer` 和 `[OK] wechat-article-writer`，当前窗口才算正式写作环境
- 少任意一个，都不能把当前窗口里产出的内容叫做“已完成双 skill 写作”
- 就算两个 skill 都已注入，只要正式优化稿还没落盘，`scripts\run-gzhrb-postwriting-pipeline.cmd` 也不会继续执行后半段
- 就算你已经运行过 `mark-*complete.ps1`，如果文件证据不成立，后半段仍然不会放行

## 八、最常用的 5 个日常操作口令

### 1）只跑今天的 48 小时报

直接双击：

```bat
scripts\ai-daily-digest-launcher.cmd
```

或者对 agent 说：

```text
请在项目目录先跑一份 48 小时、Top 15、中文的 AI 日报。
```

### 2）从日报里挑题，写今天这篇

对 agent 说：

```text
先跑 48 小时日报，然后从日报里挑一个最适合写成长文的题材，先给我候选判断，再继续写成公众号初稿。
```

如果你要继续进入正式双 skill 写作，先在项目目录执行：

```bat
scripts\check-codex-required-skills.cmd
```

### 3）把今天这篇继续走完

对 agent 说：

```text
把今天这篇继续走完整条链路：发文态优化、插图规划、插图生成、归档、图片回填、发布包装。
```

### 4）写作完成后，把这篇继续走完

直接运行：

```bat
scripts\run-gzhrb-postwriting-pipeline.cmd "E:\WorkCodex\ai-daily-digest\reports\gzhrb\articles\<article-id>\article.md"
```

### 5）看最近日报抓取健康情况

直接运行：

```bat
scripts\analyze-ai-digest-health.cmd
```

## 九、你的日常推荐操作

如果按你现在这套工作方式，最推荐的是：

### 轻量模式

1. 先用脚本跑 `48 小时日报`
2. 再在 Codex / Claude Code 里让 agent 帮你挑题和写稿

适合日常大多数情况。

### 一键脚本模式

1. 先运行 `scripts\run-digest-gzhrb-publish-pipeline.cmd`
2. 再由外部双 skill 写完正文
3. 最后运行 `scripts\run-gzhrb-postwriting-pipeline.cmd "<article-path>"`

适合你今天只想把链路跑通，不想人工细拆。

### 正式内容模式

1. 先跑日报
2. 再让 agent 按 AI杨侦探正式工作流继续执行

这是最符合你当前项目定位的方式。

## 九、一句话结论

以后你就按这条判断：

- 只要“生成日报”，用 `cmd`
- 只要“跑到正式写作关口”，用 `scripts\run-digest-gzhrb-publish-pipeline.cmd`
- 只要“写作后的插图、归档、定稿、包装”，用 `scripts\run-gzhrb-postwriting-pipeline.cmd "<article-path>"`
- 只要“涉及选题、写作、优化、配图风格控制”，直接在 Codex / Claude Code 里提需求
- 只要“准备进入双 skill 正式写作”，先跑 `scripts\check-codex-required-skills.cmd`
