# 公众号 SVG 排版与验收

以用户确认的正文为准，先独立保存博客 Markdown，再把文章改编为有角色、场景、分镜和适量动画的公众号版本；两版事实、观点与信息应一致，允许为画面适度改写。正文不能因分镜压缩而丢失核心信息。公众号代码可使用多个内联 `<svg>` 与容器组成一个完整 HTML 代码文件；如果必须交付 `.svg`，则需要有效的单根 SVG。普通排版 HTML、截图或纯 PNG 都不能冒充 SVG。当前项目的发布打包脚本不生成 SVG。

## 参考案例：EARS 动画文章

参考：[小耳和阿卡｜往下滑，看她俩，干了啥](https://mp.weixin.qq.com/s/gvFKcCyp1ToBkKVwPmGV4Q)。2026-11-13 通过已加载网页 DOM 检查到：

- 正文中有 19 个 SVG，其中前 12 个是 750 宽的连续主画面，使用不同的 `viewBox` 纵向范围；其余包含辅助图形和其他内容。主画面放在容器中，片段之间有少量重叠以衔接。数字反映当次检查，不保证文章或平台永不变化。
- SVG 使用 `path`、`rect`、`line`、`circle` 和大量 `<image>`；图像引用 `mmbiz.qpic.cn` 上的微信素材。角色的不同表情或姿态可作为多个素材分层，配合透明度切换；`<g>` 可组织部件并应用整体变换。
- 动画以 SVG 原生 `animate`、`animateTransform`、`set` 实现，涉及透明度、平移、缩放和线条绘制等。所检查元素中大量 `begin` 是按秒计的时间偏移，不能据此声称是随滚动触发；页面另有视频，不能将视频效果算作 SVG 动画。不同设备及微信版本是否保留这些特性，需要实际验证。
- 当次检查未发现正文 SVG 内的 `<text>` 元素，存在许多 `<path>` 与图片；无法仅凭 DOM 确认每段文字原先如何制作。路径化文字有利于固定字形，但不易编辑和检索。默认保留可编辑源稿，重要正文优先使用清晰可读且可核对的文字呈现方式，再按设备实测选择是否转路径。

不要复制参考文章的原创人物、插画或具体版面，学习其分镜、素材分层与动画方法，创作 AI杨侦探自己的视觉语言。

## 每篇文章的制作流程

1. **定稿**：保存可独立发布博客的最终 `article.md`，保留标题、全文、必要图片及有效引用；在改编期间同步核对事实与修改，不用公众号画面取代博客稿。
2. **分镜**：先提炼主线，把问题、变化、操作与结论编排成连续画面；画面承担信息，文字少而清楚，重要结论和限制仍须准确呈现。每幕标明对应原文、画面、角色动作、文案、素材、动画及预计尺寸，不默认使用“正文段落加人物卡片”。用户提供或已认可样稿时复用其视觉方向；复杂文章可先做开场与一个正文场景的短样，不强制额外审批。
3. **场景与素材**：优先使用 `E:\WorkCodex\ai-daily-digest\AI杨侦探角色素材\` 中用户认可的角色；保持脸部、眼镜、服装及配色一致。先设计人物、环境与物件前后关系自然的完整场景，再根据分镜准备需要移动的独立人物部件、窗口、前景、背景和遮挡补画。参考素材的可编辑性依实际文件判断；不要将完整插画当作可独立运动的分层源。产品操作优先使用真实截图，概念画明确标注为示意，不能伪装真实界面。
4. **排版和动画**：依据分镜制作连续 SVG 场景，先保证静态画面、重要信息与移动端字号完整可读，再制作图层或序列帧动画；关键内容不能只在动画执行后出现或读得过快。明确报告实际交付是①静态绘本画面、②叠加图形的局部动画，还是③人物或场景本身可独立运动的分层动画；不能因有动画标签就声称整幅画或角色已动起来。多个片段若用 HTML 容器组合，应保存为完整代码文件，不能将多个并列根节点伪装成单个有效 `.svg`。
5. **图片上线**：建立实际使用素材与微信地址的映射，逐项核对画面、文件和地址；本地版本与公众号代码分开标明。缺少地址时先做本地样稿，集中列出文件和缺失地址；不得声称样稿已能在公众号显示。不要将本地预览地址、临时链接或 Base64 当成已在微信验证的素材。
6. **发布验证**：本地预览后，交付公众号完整代码；实际导入、保存、重新打开以及手机微信预览分别验证。若依赖编辑器、F12 或第三方工具，按现场实际情况说明步骤与限制，不保证任一导入方式一定支持。

分镜、实际使用的完整场景原图、动画独立图层或序列帧、可编辑源码及各片段作为支持文件归档在同一文章文件夹；标注可复用素材来源，个人原照片不默认复制进公开发布包。最终答复仍突出博客 Markdown 和公众号完整代码两份成品。

## 排版基线

- 默认延续 AI杨侦探暖白底、森林绿和少量铜色的编辑风，并以卡通角色和场景讲故事，用户指定的风格优先。标题、正文、注释控制在 2–3 级字号；章节标题要有足够对比。使用可回退的系统中文字体，不承诺不同手机字形完全一致。
- 以手机宽度设计：统一文字栏宽、字号和行距；按实际可用宽度换行，段落与图文之间留足空间。不要靠拉伸字间距强行两端对齐；短行和段尾自然左对齐。装饰线、章节编号和留白建立层次，不把正文塞进固定高度的小框。
- 依据实际行数计算每个区块高度及其后元素位置；长文分段、长图按正确比例缩放，避免文字相互覆盖、超出边界或被裁切。代码和表格需要单独处理，不能丢失内容。文字应保留为 SVG 文本，除非用户明确要求转图。
- 使用 `viewBox` 和适配宽度。图片优先使用用户提供、公众号可访问的微信素材地址，XML 中 URL 的 `&` 写为 `&amp;`；不使用本地路径或大段 Base64。无法确定图片对应关系时先核对，不猜测。

## 实际验证

1. 检查内容、事实、必要限制和素材映射。单根 `.svg` 检查 XML 可解析且根节点为 SVG；多段 HTML 检查容器中各 SVG 片段和引用完整，不把 HTML 当作单根 SVG 校验。检查图片是否实际加载及比例是否正确；文件存在或 URL 可访问不等于公众号可显示。
2. 以手机宽度本地预览全文，检查文字、图片、分镜衔接、遮挡和裁切；检查加载后、等待后、滚动到后半段，以及动画不播放时的静态画面。对动画观察不同时刻的真实画面变化，单张截图或存在动画标签不足以证明播放正常。本地效果不代表微信内一致。
3. 用户导入公众号后，分别验证后台保存、重新打开及手机微信预览，逐段核对字号、换行、图片、动画、文字覆盖和场景衔接；发现问题回到源文件修改再导入。报告分别列出已验证、未验证、缺失素材或地址，不把本地预览称为公众号预览通过。

公众号可能对导入或 SVG 特性进行处理，不能保证所有后台或设备表现相同。保留可恢复的源文件；发布由用户决定。
