# AI杨侦探插图风格规范 v7（历史参考）

> 本文件保留早期视觉探索记录，不再作为当前 Prompt 的主规则。当前规则以 `docs/superpowers/specs/2026-04-21-ai-yang-detective-illustration-prompt-rules.md` 为准，Profile 参考见 `docs/illustration-visual-profiles.md`。

## 文档目的

这份文档用于固定 `AI杨侦探` 账号在公众号文章、日报转长文、封面图、正文结构图中的默认插图风格。

它服务的不是“任意一张 AI 图片”，而是 `AI杨侦探` 账号长期发布中的整套视觉语言。目标是让后续工作流可以尽量一键化，但最终输出依然保持统一、稳定、低 AI 感，并在手机端兼顾美观、清晰和信息量。

适用场景：

- AI 日报转公众号稿
- AI 工具观察稿
- Agent / 编程 / 工作流 / 基础设施类文章
- 长文封面图
- 正文结构图
- 配图回填到 Markdown 的最终发布链路

---

## 一、风格定位

`AI杨侦探` 的插图，不走典型 AI 内容账号常见的深蓝、深紫、霓虹、赛博科技路线。

它的目标不是让读者一眼觉得“这是 AI 图”，而是让读者觉得：

- 这是一个有判断力的内容账号
- 这是编辑部认真做出来的配图
- 这张图在帮我理解文章，而不是只在制造氛围
- 它有质感，但不浮夸
- 它有设计感，但不抢文章本身的戏

一句话定义：

**浅底编辑图解风：用清楚的标题、结构、对照、流程和少量轻 3D 拟物物件，帮助读者一眼理解文章判断；不做赛博海报，也不把图压成空洞极简场景。**

### 1.1 默认画面标准：清晰编辑图解

每张正文插图必须同时做到：

- **好看**：有明确画面重心、层级、干净光线和轻 3D 物件，不像廉价模板、复古机器或空白素材图。
- **看得清**：主物件、关键关系和文字在手机文章宽度下仍容易辨认；不依赖放大才能理解。
- **讲得明**：一个中心判断配四到八个有效信息点；信息来自模块、状态、流程、对照、物件和短标签，不来自大段说明文字。

推荐结构是“标题 + 主体结构 + 结论或视觉收束”。六月基线优先采用稳定、平衡、规整的编辑排版：分类、对比和流程类主题可用分组模块、对照列和卡片，但不要把所有图片强行压成同一块信息板。标题、核心判断、证据和结论必须有明确主次，画面要像编辑设计完成的杂志图解，而不是通用仪表盘或 SaaS 引导页。

信息密度来自有价值的模块、图标、对照、步骤和短标签，不来自大段文字，也不等于把画面压到极简。每张图可以有一个中心物件、中心结构或中心结论；分类表可使用规整网格，对比图可使用左右分区，流程图可使用路径。关键是让画面服务这一张图的解释任务，而不是套用一个固定布局。

标题默认位于顶部居中，占画面约 `12%` 到 `18%` 高度，使用高对比深绿色大字；当左侧主物件非常明确且标题需要避让时，才允许左对齐。标题是图片自己的判断或问题，不照抄整篇文章标题；不使用副标题、顶部说明句或冗长标语。

默认渲染方式是**六月编辑图解基线**：`70%` 结构化图解加 `30%` 轻 3D 拟物物件。卡片、屏幕、容器、芯片、文件或设备要有适度厚度、柔和阴影和高级印刷质感；背景使用暖奶油纸面、很轻的印刷纹理、低对比粉棕色块，以及少量边角笔记本或纸张。不要做成纯白 UI 示意图，也不要使用脏旧纸、强颗粒、做旧金属、机械管线或复古工厂。

### 1.2 文章级叙事与 Profile 规则

一篇文章的插图是一组连续叙事，不是同一场产品展厅的不同角度。

- 规划时先选择文章类型 Profile，再给每张图指定一个叙事角色；若角色与前图重复，应合并或改为新的真实使用场景。
- 全局规则只约束清晰度、视觉身份、文字安全与去重，不应把某一篇产品文章的画法强加给其它文章。
- 模型发布类才采用“产品入口、官网页面、发布会大屏、品牌展厅最多一张”的限制；趋势、教程、工作流和实战文章应按自身 Profile 组织图片。
- 所有 Profile 都不得复用同一场景、同一组设备和同一人物姿势；每张图必须承担不同叙事任务。

Profile 定义、推荐角色和专用限制见 docs\illustration-visual-profiles.md。

## 二、核心气质

这套风格要同时满足 5 个关键词：

- `高级感`
- `质感`
- `编辑感`
- `结构感`
- `低 AI 感`

### 1. 高级感

不是靠复杂、发光、炫技来实现，而是靠克制、留白、比例、颜色关系和信息层级。

### 2. 质感

不是重渲染，不是写实金属，不是电影海报，而是有一点材料感、纸面感、卡片感、拟物感。

### 3. 编辑感

图像看起来像“内容编辑系统的一部分”，像专栏图、专题图、结论图，而不是随机生成的一张概念图。

### 4. 结构感

图要能解释关系。尤其适合：

- 对比
- 流程
- 结构
- 分层
- 框架
- 关键结论

### 5. 低 AI 感

要避免一眼就是 AI 生图常见套路：

- 泛滥发光
- 赛博紫蓝
- 空中漂浮 UI
- 无意义科幻线框
- 虚假的未来城市
- 过饱和冷色对撞
- 机械感过强的人形角色

## 三、适用文章类型

这套风格主要服务于 `AI杨侦探` 当前最常见的内容类型：

- AI 工具观察
- 工作流分析
- Agent / skill / 自动化相关文章
- 模型、平台、产品的对比判断
- 技术趋势解读
- 方法论文章
- 个人工作流体感文章

它特别适合这样的文章语气：

- 有判断，但不端着
- 有观点，但不喊口号
- 有方法，但不讲课
- 是在认真讲一件打动自己的事

## 四、视觉构成原则

整体视觉系统采用：

**编辑信息图解 + 轻 3D 拟物物件**

比例建议：

- `65% 清晰结构与信息层级`
- `20% 标题和结论阅读层级`
- `15% 轻 3D 物件与材质辅助`

也就是说，插图先要让读者从居中标题进入，再一眼看清核心物件和关系，最后由结论区或视觉收束带走判断。它不是海报式大标题，也不是水彩绘本或纯氛围插画。

### 4.1 图解类应优先承担的任务

适合用图解的内容：

- 一个核心判断
- 两种路径的对比
- 工作流流程
- 系统结构
- 层级关系
- 因果关系
- 文章结论归纳

推荐图像类型优先级：

1. `scene + comparison`
2. `scene + framework`
3. `comparison`
4. `framework`
5. `flowchart`

说明：

- `scene` 不再只是补充，可以成为主结构
- 图解的任务从“完整解释机制”调整为“帮助读者一眼看懂一个判断”

### 4.2 轻 3D 场景的作用

轻 3D 场景不是为了“酷”，而是为了增强记忆点。

适合表现：

- 关键物件
- 文章的象征性意象
- 产品 / 芯片 / 控制台 / 设备 / 标签 / 卡片
- 某个核心概念的具象化承载物

轻 3D 场景必须满足：

- 构图简洁
- 物件数量少
- 物件清楚、完整、圆润
- 有轻微拟物感，但不追求重写实
- 有材料感，但不过度反光
- 不要复杂环境，不要戏剧化布景
- 可以自由排版，不强制中心对称
- 允许不规则布局，只要主次清楚

## 五、色彩规范

### 5.1 主色系统

账号默认主色建议定为：

- 背景主色：`#F6F1E8`
- 深结构色：`#27403A`
- 柔和强调色：`#D8BFC5`
- 质感提亮色：`#A56A43`
- 正文字色：`#2B2B2B`

这套色彩关系的目标不是强烈撞色，而是：

- 有对比
- 有层次
- 有情绪
- 但不廉价、不浮夸

### 5.2 色彩角色分工

`#F6F1E8`

- 主背景色
- 用于大面积留白
- 提供纸面感和编辑感

`#27403A`

- 结构骨架色
- 用于手绘线稿、物件边界、阴影和重点物件
- 提供稳定感、判断感和账号识别度

`#D8BFC5`

- 柔和强调色
- 用于辅助物件、次重点区域和层次区分
- 提供细腻感，不抢主体

`#A56A43`

- 少量提亮色
- 用于关键物件、小面积高光和必要标记
- 使用面积应小于深绿色

`#2B2B2B`

- 正文标题和关键文字
- 保证可读性
- 避免纯黑太硬

### 5.3 色彩禁区

避免以下方向成为主色：

- 深蓝
- 深紫
- 蓝紫渐变
- 赛博青
- 霓虹粉紫
- 黑底荧光科技色
- 高饱和荧光绿

这些颜色不是绝对不能出现，但不能成为默认气质。

### 5.4 分类强调色

默认色盘只定义账号底色和结构色，不应让每张图都落成单一棕绿配色。插图规划应为每张图指定一到两个“有职责”的低饱和强调色：

- 雾蓝 `#6E9CCF`：搜索、信息、数据、连接
- 鼠尾草绿 `#779B86`：工具、工作流、完成状态
- 琥珀黄 `#D6A447`：行动、决策、提醒
- 珊瑚粉 `#D98578`：创作、人物、对照

强调色只能用于类别页签、关键路径、任务物件或结果，不要同时铺满所有颜色，也不要用成霓虹渐变。这样既保留六月基线的编辑感，也让分类、对比和流程图在手机端有更强辨识度。

## 六、背景规范

默认背景应为：

- 以 `#F6F1E8` 奶油白为底的干净暖色场景
- 低对比灰粉或铜棕的不规则色块，用来组织空间，不做旧、不起雾
- 有明确的地面、桌面、墙面或产品体验空间关系
- 不是纯白留空，也不是抽象纸张画布、完整风景画或泛化样板间

背景要有“插画画布感”和“编辑纸张感”：读者能感到画面在一个温和的环境里发生，但背景不抢主体，也不把图变成房间或舞台。

背景选择规则：

- 默认使用“暖色纸感底 + 两到三块有机色块 + 轻量地面或背景轮廓”。这是技术解读、模型观察、工作流分析文章的默认背景：既保留账号统一感，也避免画面显得太白、太空。
- 只有文章本身在讲一个明确的生活或使用现场时，才允许使用简化的彩色场景背景；场景必须直接承担文章信息，不能只是为了填满画面。
- 即使使用场景背景，也只保留一个低矮地面或一个简化环境轮廓，不能变成风景插画。

允许的背景处理：

- `#D8BFC5` 的低对比不规则平面色块
- `#A56A43` 的极淡边缘暖雾或地面阴影
- 干净的柔和渐层、清楚的地面或桌面、简化的墙面与环境轮廓
- 真实但克制的光影方向，例如窗侧自然光、屏幕补光或室内顶光

不允许的背景处理：

- 星空
- 发光网格
- 赛博城市
- 大面积光束
- 复杂透视空间
- 漂浮 HUD 科技界面
- 高密度粒子和无意义装饰线
- 纯白空背景和无意义的大面积留白
- 纸张纤维、颗粒噪点、脏污、褪色、做旧划痕和泛黄效果
- 复古工厂、重型机械、外露管线、发电机、传送带式 AI 装置
- 无意义的盆栽、书架、咖啡杯、台灯等“桌面布景包”，以及山水、城市、云鸟等背景元素

## 六点五、清晰度规范

公众号正文图的第一验收标准是缩小后仍然看得懂，而不是放大后看起来有多少纹理。

- 主体物件边缘必须清楚，使用稳定的中等粗细墨绿轮廓线。
- 主体与背景之间必须有明显色差，避免奶油白叠奶油白、灰粉叠灰粉。
- 小图标、细虚线、纸张颗粒和装饰纹理不能成为理解图片的必要条件。
- 文字、核心物件和关系线在手机宽度下仍需一眼辨认。
- 禁止软焦、重雾化、景深模糊、脏颗粒和为了“质感”牺牲边缘清晰度的处理。
- 允许细腻渐层、轻材质和柔和投影提升美观，但主体轮廓、文字和信息物件不能因此变糊。
- 每张图默认保留一个中心主体、四到六个有效信息物件，以及三到六个可读的物件标签。

### 6.6 屏幕与文字内容规则

- 屏幕应像真实产品或工作界面，但只展示可核对的短标签、简短代码行、列表块、图表轮廓或结构化占位内容。
- 不得在画面中生成大段中文正文、长篇论文引用、复杂公式、虚构资料来源或无法核验的产品 UI 文案。
- 单个屏幕最多保留 1 到 3 个短标签；整张图维持 3 到 6 个可读短标签即可。
- 标签应嵌入屏幕页签、文件封面、任务卡、笔记本或评估表，不使用悬浮招牌、巨型品牌墙或舞台字幕。
- 真实感来自明确任务、人物动作和空间关系，不来自堆满屏幕的界面细节。

## 七、版式规范

这套风格不是自由艺术画面，而是有信息组织的。

优先使用的版式：

- 一个具体人物或小群体 + 能看懂关系的物件
- 同一个空间里自然发生的双路径或双选择
- 一侧主体、一侧留白或环境，而不是一侧主体、一侧信息栏
- 有动作、有距离、有状态差异的轻量对照场景
- 单一主物件 + 环境线索，不附加结论词

可以使用但不应默认套用的版式：

- 左右镜像对照
- 上下流程
- 中心主体 + 周围结构
- 模块化卡片
- 表格化结论

版式目标：

- 一眼看懂重点
- 图像和段落意思呼应，用图片自己的短标题明确这一张图的判断或问题
- 结构层次清楚
- 留白足够
- 不挤、不乱、不炫
- 看起来像编辑做的，不像模板拼的

避免：

- 满画面堆东西
- 主次不分
- 视线没有落点
- 过度复杂的透视关系
- 同时出现太多概念
- 所有图都长成同一种“框架图”
- 为了显得专业而强行塞模块、箭头、卡片

---

## 八、文字与标签规范

默认使用“标题 + 短标签 + 图解”的少量文字体系。正文承担完整论证，插图负责把结构、对照、步骤和结论压缩成可扫读的信息。

要求：

- 默认允许一个图片短标题、三到八个短标签，并在确有必要时使用一个短结论区
- 标题默认顶部居中；标签可嵌入模块、图标、文件、屏幕、流程节点或对照区
- 结论只能是一句可核对的短判断，不放段落说明或口号

极少数适合放进图里的文字：

- 图片自己的短标题
- 物件上的极短名称与不可省略的术语
- 模块、步骤、对照维度和一个短结论

不适合放进图里的文字：

- 大段正文
- 太长的解释句
- 密集小字
- 整篇文章标题、段落标题、副标题
- 顶部说明句、底部大段说明、海报式标语
- Logo 模拟
- 水印式无意义标题
- 一张图里塞太多标签

---

## 九、物件与形体规范

如果画面里出现物件，优先选择：

- 卡片
- 芯片
- 屏幕
- 控制台
- 模块盒子
- 标签牌
- 简洁设备
- 结构化容器

物件必须优先表现“具体任务”，而不是一组没有用途的图标。例如代码类用编辑器、文件树、调试标记与终端；搜索类用资料堆和放大镜；办公类用文档、表格、日历与完成标记；接入类用端点、连接线和权限锁；创作类用画布、镜头、音轨或剪辑片段。图标要有可识别的对象语义、轻厚度和材料感，不能退化成贴纸式抽象符号。

物件表现要求：

- 圆角
- 轻 3D
- 有一点厚度
- 有干净阴影
- 有材料感
- 但不追求照片级写实

避免：

- 复杂机械装置
- 过于科幻的机器人
- 金属细节过多
- 写实人物脸
- 夸张反射
- 廉价 3D 电商图感

---

## 十、人物与角色规范

默认情况下，人物不是主角。

如果必须出现人物或角色：

- 用简化角色
- 用拟物小角色
- 用抽象小人
- 不做写实脸部
- 不做高情绪表演
- 不做强 IP 卡通感

人物的作用应该是：

- 说明关系
- 强化对比
- 给结构图一点活性

而不是让画面变成角色海报。

## 十一、文章中的插图分工

默认一篇文章的插图应承担不同任务，而不是每张图都在做同一件事。

建议分工如下：

### 第一张

- 开篇定调图
- 让读者知道这篇到底在讲什么
- 类型通常是 `scene` 或 `scene + framework`

### 第二张

- 解释核心差异
- 通常用 `comparison` 或 `scene + comparison`

### 第三张

- 解释机制或过程
- 通常用 `flowchart`、`framework`，或者更轻的“关系提示图”

### 第四张

- 收束结论
- 通常用 `scene + framework` 或“结论型轻场景图”

也就是说，插图不是“配几个好看的图”，而是文章结构的一部分。
但它也不是每张都要做成解释板。对判断文、观察文、体感文来说，适当的轻场景图更容易让人记住。

## 十二、与旧风格的区别

此前默认跑出来的图，更接近：

- 深色科技媒体风
- 蓝青冷光
- 系统控制台感
- 工程结构图

新的 `AI杨侦探` 风格，要在保留“结构清楚”的前提下，明显切换到：

- 浅底
- 编辑感
- 温和色彩
- 更少 AI 科技套路
- 更像内容品牌自己的视觉系统

一句话：

**保留结构解释力，去掉深色 AI 味。**

## 十三、默认生成参数

为了确保后续一键化稳定，建议默认技术参数固定为：

- 比例：`16:9`
- 质量：`2K`
- 默认风格：`图解 + 轻 3D 场景混合`
- 默认背景：浅底
- 默认色彩：`#F6F1E8` / `#27403A` / `#D8BFC5` / `#A56A43`
- 默认目标：低 AI 感、高编辑感、高可读性

## 十四、验收标准

以后每次生成完一张图，都可以用这 5 条快速判断它合不合格：

1. 这张图像不像一篇认真内容文章的配图，而不是 AI 海报？
2. 这张图是不是在帮文章解释结构，而不是只在制造气氛？
3. 这张图有没有避开深蓝紫赛博感？
4. 这张图有没有留白、层次和可读性？
5. 这张图有没有一点自己的品牌气质，而不是标准科技号模板？

只要这 5 条里有 2 条以上答不上来，这张图就不应该直接用。

## 十五、工作流落地要求

这份规范用于后续工作流默认配置，具体落地要求如下：

### 1. 风格选择

默认风格不再使用深色 `engineering-media` 作为账号总默认风格，而是切换到本规范定义的浅底编辑图解风。

当前已落地到本机默认配置：

- `preferred_style = ai-yang-detective-editorial`

同时，默认生图画幅已固定为：

- `default_aspect_ratio = 16:9`
- `default_quality = 2k`

### 2. 文章级归档

每篇文章的插图资产仍然必须保持文章级归档：

```text
reports/gzhrb/illustrations/<article-id>/
```

目录内至少包含：

- `outline.md`
- `batch.json`
- `prompts/`
- 生成图片文件

### 3. Markdown 回填

生成完成后，必须将图片相对路径回填到文章 Markdown 中，不能只停留在图片生成阶段。

### 4. 标题 / 引导语 / 标签

插图完成后，仍然需要补齐：

- 标题备选
- 引导语
- 话题标签

最终形成完整发布单元。

## 十六、最终一句话规范

**AI杨侦探插图风格：浅底编辑信息图解，用顶部居中的短标题、主体图解、三到八个短标签与可选底部结论，讲清一个判断、对照或流程。使用奶油白、墨绿、灰粉与少量铜棕，有明确阅读层级，不做海报口号、通用仪表盘或无层级卡片墙。**
