# `ai-yang-detective-content-pipeline` Skill 规格草案 v0

## 1. Skill 名称

建议英文 skill id：

`ai-yang-detective-content-pipeline`

建议中文工作名：

`AI杨侦探日报到公众号工作流`

### 命名理由

- 这是一个总控型 workflow skill，不是单一写作 skill
- 名称里保留 `content-pipeline`，能明确表达它是“内容生产链路”
- `ai-yang-detective` 用于绑定账号场景，避免与通用写作 skill 混淆

---

## 2. 触发词

这个 skill 不应该在“普通写文章请求”上广泛触发，而应该在“日报驱动 + 公众号生产链路”场景下触发。

### 2.1 全链路触发

当用户表达要从日报一路跑到发文包时触发：

- 跑今天的内容工作流
- 从日报里挑题写今天这篇
- 跑今天这篇公众号稿
- 从日报到公众号稿跑一遍
- 跑 AI杨侦探工作流
- 今天这篇从日报开始做
- 跑今天的发文链路

### 2.2 中途续跑触发

当用户已有日报、已有题材或已有文章，想从中途继续时触发：

- 从今天日报里挑一题继续写
- 继续今天这篇
- 继续这篇公众号稿
- 给这篇配图并归档
- 把这篇整理成可发布版
- 给这篇补标题和引导语
- 把这篇走完完整链路

### 2.3 状态驱动触发

当用户说法较短，但明显想让系统识别当前阶段继续推进时触发：

- 接着跑这篇
- 继续这条内容链
- 继续今天这个选题
- 把这篇走到发文包
- 这篇还没做完，继续

### 2.4 不应触发的情况

以下场景不应由这个 skill 接管：

- 用户只想单独写一篇普通文章
- 用户只想润色一段文案
- 用户只想单独生成一张图
- 用户只想跑日报，不需要后续选题和公众号稿
- 用户只问标题、引导语或标签

这些请求应继续交给现有 skill。

---

## 3. 阶段顺序

这是一个总控型 orchestrator skill，职责是调度整条链路，而不是重写底层能力。

推荐阶段顺序如下：

### 阶段 1：生成日报

- 跑 `48 小时日报`
- 生成日报 Markdown
- 将日报作为当天候选题材池

### 阶段 2：候选题材提取

- 从日报中提取适合展开成长文的候选题材
- 输出候选清单和简要判断
- 不直接进入写稿

### 人工关口 A：选题判断

- 判断候选题材是否适合公众号长文
- 不适合的直接淘汰
- 选出当天最适合的一题
- 若没有合适题材，则停止并返回判断结果

### 阶段 3：长文初稿生成

- 对选中的题材调用 `khazix-writer`
- 输出公众号长文初稿 Markdown

### 阶段 4：发文态优化

- 调用 `wechat-article-writer`
- 将初稿优化成更适合真实发文的状态
- 优化开头、结构、手机端可读性和公众号语感

### 阶段 5：插图规划

- 调用 `baoyu-article-illustrator`
- 分析文章结构与视觉机会点
- 生成插图规划、prompt 文件、批量任务定义

### 阶段 6：插图生成

- 继续由 `baoyu-article-illustrator` 负责执行插图生成链路
- 不再将“生图阶段”在工作流层面对外表述为任何独立工具名
- 工作流层面对外统一口径为：插图规划与插图生成同属 `baoyu-article-illustrator`

### 阶段 7：归档与回填

- 自动将插图资产归档到文章专属目录
- 自动将图片相对路径回填到 Markdown 正文
- 确保图文不分离

### 阶段 8：发布包装

- 补齐标题备选
- 补齐引导语
- 补齐话题标签
- 输出最终发文包

### 人工关口 B：终审

- 检查文案是否需要继续调整
- 检查配图是否需要重跑
- 检查标题 / 引导语 / 标签是否合适

### 人工关口 C：通过发布

- 若通过，则工作流结束
- 若不通过，允许回退到对应阶段继续迭代

## 4. 与已有 skill 的关系

这个新 skill 是总控 skill，不负责替代底层 skill。

它与已有 skill 的关系应明确写清：

### 4.1 直接复用的 skill

- `ai-daily-digest`
  - 负责日报生成
- `khazix-writer`
  - 负责长文初稿
- `wechat-article-writer`
  - 负责发文态优化
- `baoyu-article-illustrator`
  - 负责插图规划、插图生成、归档与回填链路

### 4.2 仅在设计 / 维护 skill 时相关的 skill

- `brainstorming`
  - 用于工作流设计、风格设计、流程重构
- `meta-skill`
  - 用于编写和维护这个 skill 自身

### 4.3 不应替代的 skill

本 skill 不应替代：

- 单独写文章的 skill
- 单独配图的 skill
- 单独跑日报的 skill

它只在“你要跑整条链路”时触发。

### 4.4 关键关系约束

- 报日阶段：调用 `ai-daily-digest`
- 初稿阶段：调用 `khazix-writer`
- 优化阶段：调用 `wechat-article-writer`
- 配图阶段：统一调用 `baoyu-article-illustrator`
- 工作流层面不再把第 8 步单独表述成任何独立出图工具

## 5. 默认风格和归档规范

### 5.1 默认插图风格

默认采用：

`AI杨侦探插图风格 v1`

核心定义：

- 浅底编辑图解风
- 图解 + 轻 3D 场景混合
- 默认比例 `16:9`
- 默认质量 `2K`
- 主色：
  - `#F6F1E8`
  - `#27403A`
  - `#D8BFC5`
  - `#A56A43`
- 避免深蓝、深紫、霓虹、赛博科技感

### 5.2 当前默认配置落点

目前默认风格配置已落地到：

  - `preferred_style = ai-yang-detective-editorial`
  - `default_aspect_ratio = 16:9`
  - `default_quality = 2k`

### 5.3 归档规范

每篇文章的插图资产必须归档到文章专属目录：

`reports/gzhrb/illustrations/<article-id>/`

目录内至少包含：

- `outline.md`
- `batch.json`
- `prompts/`
- 插图文件

### 5.4 Markdown 回填规范

文章正文中的图片引用必须使用相对路径，且指向该文章自己的插图目录。

示例：

`illustrations/<article-id>/01-xxx.png`

### 5.5 文章产物规范

文章成稿默认放在：

`reports/gzhrb/`

如存在风格化改写版或最终发文版，也必须保持可追溯命名，不允许散落在公共目录或临时路径。

## 6. 最终交付标准

这个 skill 的“完成”不能只定义成“文章写完了”，必须定义成一个完整发布单元已经形成。

### 6.1 完成条件

只有在以下条件全部满足时，才算完成：

1. 已生成当天 `48 小时日报`
2. 已从日报中筛出并确认一个适合公众号长文的题材
3. 已生成该题材的公众号长文初稿
4. 已完成发文态优化
5. 已完成插图规划与插图生成
6. 插图已按文章专属目录归档
7. 图片已回填到文章 Markdown
8. 已补齐标题备选、引导语、话题标签
9. 已形成最终发文包

### 6.2 最终发文包必须包含

- 一篇优化后的 Markdown 文章
- 一个文章专属插图目录
- 标题备选
- 引导语备选
- 话题标签

### 6.3 允许回退的阶段

如果终审发现问题，skill 必须允许回退：

- 文案问题 -> 回退到 `wechat-article-writer`
- 插图问题 -> 回退到 `baoyu-article-illustrator`
- 只改标题包装 -> 回退到发布包装阶段
