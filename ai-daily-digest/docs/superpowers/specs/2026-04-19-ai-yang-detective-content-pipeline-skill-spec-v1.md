# `ai-yang-detective-content-pipeline` Skill 正式规范 v1

## 1. Skill 名称

- skill id: `ai-yang-detective-content-pipeline`
- 中文工作名：`AI杨侦探日报到公众号总控工作流`
- 类型：总控型 orchestrator skill

### 1.1 定位

这个 skill 的本体不是“写作器”，也不是“配图器”，而是一个状态驱动的内容生产总控器。

它负责：

- 判断当前请求处于哪一阶段
- 调度已有 downstream skill
- 维护文章级资产边界
- 保证最终交付是一个完整发文单元

它不负责：

- 重写 `khazix-writer`
- 重写 `wechat-article-writer`
- 重写 `baoyu-article-illustrator`
- 在没有人工确认选题的情况下自动决定当天最终题目

---

## 2. 触发规范

### 2.1 应触发的请求类型

当用户意图属于以下任一类时，应触发本 skill：

- 从 `48 小时日报` 开始一路跑到公众号发文包
- 从某个中间状态继续推进到发文包
- 对现有日报 / 现有文章 / 现有插图资产进行状态识别后续跑
- 明确要求跑 `AI杨侦探` 这条完整内容工作流

### 2.2 触发示例

以下表述应触发本 skill：

- `跑今天的 AI杨侦探工作流`
- `完整跑一遍 48 小时日报，然后挑一个最适合写成长文的题材`
- `从日报里挑一题，直接做成公众号发文包`
- `继续今天这篇，把图也配完并归档`
- `这篇已经写完了，再走完标题、引导语、标签和插图`
- `从这篇日报继续，不要重跑前面的`
- `把这条内容链跑完`
- `今天这篇从选题开始做`

### 2.3 不应触发示例

以下场景不应由本 skill 接管，而应转交单点 skill：

- `帮我写一篇公众号文章`
- `帮我润色这段文案`
- `给这篇文章补几个标题`
- `帮我只生成一张头图`
- `只跑今天的 48 小时日报`
- `只做文章配图，不改正文`

### 2.4 触发判定原则

若请求同时满足“日报上下文 + 公众号长文 + 后续包装 / 配图 / 归档”中的两个以上条件，应优先视为本 skill 的触发场景。

若请求仅涉及某个局部阶段，且没有明确要跑完整链路，则不应过度接管。

## 3. 阶段顺序

### 阶段 1：生成日报

- 运行 `48 小时日报`
- 产出日报 Markdown
- 将结果视为当天候选题材池

### 阶段 2：候选题材提取

- 从日报中提取适合扩展成长文的候选题材
- 输出候选题材清单与简短判断
- 这一阶段不直接写稿

### 人工关口 A：选题判断

- 人工判断哪些题材适合公众号长文
- 选出当天唯一主题
- 若没有合适题材，则流程停止并返回原因

### 阶段 3：长文初稿

- 调用 `khazix-writer`
- 生成公众号长文初稿 Markdown

### 阶段 4：发文态优化

- 调用 `wechat-article-writer`
- 优化结构、节奏、开头、手机端阅读体验与公众号语感
- 默认产出优化后的正文与标题备选

### 阶段 5：插图规划

- 调用 `baoyu-article-illustrator`
- 识别视觉机会点
- 生成配图规划、`outline.md`、`batch.json`、`prompts/`

### 阶段 6：插图生成

- 继续由 `baoyu-article-illustrator` 执行插图生成
- 工作流层面统一表述为：插图规划与插图生成同属 `baoyu-article-illustrator`

### 阶段 7：归档与回填

- 将生成资产归档到文章专属目录
- 将图片相对路径回填到 Markdown 正文
- 保证图文资产不分离

### 阶段 8：发布包装

- 生成引导语备选
- 生成话题标签关键词
- 汇总标题、引导语、标签并输出最终发文包

### 人工关口 B：终审

- 审查选题表达是否成立
- 审查文章是否可发
- 审查配图风格是否正确
- 审查包装信息是否可直接发布

### 人工关口 C：通过发布

- 通过则结束
- 不通过则回退到对应阶段

## 4. 与已有 skill 的关系

### 4.1 直接复用

- `ai-daily-digest`
  - 负责日报生成
- `khazix-writer`
  - 负责长文初稿
- `wechat-article-writer`
  - 负责发文态优化
- `baoyu-article-illustrator`
  - 负责插图规划、插图生成、归档、Markdown 回填

### 4.2 设计与维护相关

- `meta-skill`
  - 用于维护本 skill
- `writing-skills`
  - 用于校正规范与结构

### 4.3 关键边界

- 本 skill 是总控，不替代下游 skill
- 选题判断保留人工关口
- 第 7、8 步对外都统一归属 `baoyu-article-illustrator`
- 不再把生图阶段单独对外表述为任何独立出图工具

## 5. 默认风格与归档规范

### 5.1 默认插图风格

默认采用：

`AI杨侦探插图风格 v1`

核心方向：

- 浅底编辑图解风
- 图解 + 轻 3D 场景混合
- 高级感、质感、低 AI 感
- 默认比例 `16:9`
- 默认质量 `2K`
- 默认主色：
  - `#F6F1E8`
  - `#27403A`
  - `#D8BFC5`
  - `#A56A43`
- 避免深蓝、深紫、霓虹、赛博感

### 5.2 默认配置落点

  - `preferred_style = ai-yang-detective-editorial`
  - `default_aspect_ratio = 16:9`
  - `default_quality = 2k`

### 5.3 归档规范

每篇文章的插图资产必须归档到：

`reports/gzhrb/illustrations/<article-id>/`

目录内最少应包含：

- `outline.md`
- `batch.json`
- `prompts/`
- 已生成图片文件

### 5.4 回填规范

Markdown 正文中的图片必须使用相对路径，并指向文章自己的插图目录。

示例：

```md
![OpenAI 把工程师经验蒸馏进 skill](illustrations/gzhrb-20260419-1519-khazix/01-framework-model-vs-method-library.png)
```

### 5.5 禁止事项

- 不允许把图片散放在 `reports/gzhrb/illustrations/` 根目录
- 不允许文章引用别篇文章目录下的图片
- 不允许只生成图片却不归档
- 不允许归档完成后不回填 Markdown

## 6. 最终交付标准

### 6.1 完成条件

只有以下条件全部满足，才算完成：

1. 已生成当天 `48 小时日报`
2. 已确认一个适合公众号长文的题材
3. 已生成长文初稿
4. 已完成发文态优化
5. 已完成插图规划与插图生成
6. 插图已归档到文章专属目录
7. 图片已回填到 Markdown 正文
8. 已补齐标题备选、引导语备选、话题标签
9. 已形成可终审的最终发文包

### 6.2 最终发文包必须包含

- 一篇优化后的 Markdown 长文
- 一个文章专属插图目录
- 标题备选
- 引导语备选
- 话题标签关键词

### 6.3 交付样例

以下是一个合格交付单元的样例结构：

```text
reports/
  gzhrb/
    gzhrb-20260419-1519-khazix.md
    illustrations/
      gzhrb-20260419-1519-khazix/
        outline.md
        batch.json
        prompts/
        01-framework-model-vs-method-library.png
        02-comparison-same-model-different-environment.png
        03-flowchart-distill-experience-into-skill.png
        04-framework-personal-method-library.png
```

文章顶部或附录中还应补齐：

- 标题备选 3-5 个
- 引导语备选若干条
- 话题标签关键词 5-10 个

## 7. 失败处理与回退规范

### 7.1 失败处理原则

- 停在真实失败阶段
- 不把部分完成伪装成完整完成
- 报告失败点、影响范围和下一步动作

### 7.2 常见失败场景

- 日报生成失败
- 有日报但没有适合公众号长文的题材
- 已选题但长文初稿质量不达标
- 优化后仍不适合公众号语境
- 插图规划文件缺失
- 图片已生成但未归档到文章目录
- 图片已归档但未回填到 Markdown
- 文与图都齐了，但标题 / 引导语 / 标签缺失

### 7.3 失败回退示例

#### 示例 A：没有合适选题

状态：

- 日报已生成
- 候选题材已提取
- 人工判断全部不适合公众号长文

处理：

- 工作流在“人工关口 A”停止
- 输出“不进入写稿”的结论
- 返回候选题材淘汰原因

#### 示例 B：文章可读，但发文态不够

状态：

- `khazix-writer` 初稿已完成
- 内容有信息量，但公众号语感不足

处理：

- 回退到 `wechat-article-writer`
- 不重跑日报
- 不重跑选题

#### 示例 C：图片风格不对

状态：

- 图片已生成
- 但风格偏深蓝紫、AI 感过强

处理：

- 回退到 `baoyu-article-illustrator`
- 保留文章正文
- 重做插图规划或生图
- 重新归档并回填

#### 示例 D：图片已生成但散落

状态：

- 图片存在
- 但不在 `reports/gzhrb/illustrations/<article-id>/`

处理：

- 不算完成
- 先完成归档
- 再检查 Markdown 引用路径

#### 示例 E：只差标题包装

状态：

- 文章和配图都已完成
- 但没有标题、引导语、标签

处理：

- 仅回退到“发布包装”阶段
- 不重跑正文
- 不重跑配图

## 8. 触发与交付的最小判定清单

### 8.1 触发前应判断

- 用户是不是要跑“日报到发文包”这条链路
- 用户是不是要从中间阶段继续推进
- 请求是不是已经超出单点 skill 的边界

### 8.2 完成前应判断

- 是否存在真实文章文件
- 是否存在真实文章专属插图目录
- Markdown 是否已经引用插图
- 标题 / 引导语 / 标签是否已补齐
- 当前状态是否足够进入人工终审

---

## 9. 一句话定义

**`ai-yang-detective-content-pipeline` 是一个调度型、状态驱动、文章级资产封装的总控 workflow skill，用于把 `48 小时日报` 中的合适题材转化为可发布的 AI杨侦探公众号发文单元。**
