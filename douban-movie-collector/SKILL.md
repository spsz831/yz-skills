# douban-movie-collector — 电影收藏一键录入

用户给「电影名 + 网盘链接」，从豆瓣补全信息后写入收藏表。核心脚本负责写表，豆瓣抓取由 WorkBuddy 用浏览器工具完成。

## 目标表格

默认写入当前工作区的电影收藏表（如 `2026-09-04_电影资源收藏表.xlsx`），单 sheet「电影收藏」，
12 列：序号 / 电影名称 / 国家地区 / 年份 / 类型 / 导演 / 豆瓣评分 / 观看状态 / 收藏日期 / 网盘链接 / 提取码 / 备注。
用户未指定文件时，在工作区找文件名含「电影收藏」的 xlsx；找不到再问用户。

## 工作流

### 1. 解析输入

从用户消息中提取若干组「电影名 + 网盘链接（+ 提取码）」。支持一条多部，也接受只有电影名（链接留空，备注写"链接待补"）。

### 2. 豆瓣抓取（每部依次执行）

**实测有效的抓取链路（2026-09 验证，按序尝试，命中即停）：**

1. **suggest 接口定位条目**（最可靠，基本必通）：WebFetch
   `https://movie.douban.com/j/subject_suggest?q=<URL编码片名>`，
   返回 JSON，取第一个 `type:"movie"` 条目的 `id`。多条候选（年份/副标题不同）→ 列表给用户选。
2. **详情页抓元数据**：WebFetch `https://movie.douban.com/subject/<id>/`，
   能拿到 导演/类型/制片国家/年份/片长，**但常漏评分和简介**——漏了别重复抓，直接下一步。
3. **评分兜底**：WebSearch「<片名> <年份> 豆瓣评分」，从结果摘要取分（多条来源交叉一致才采用）；
   备注或回报中标注评分来源为搜索。简介可同时从搜索摘要截取。
4. **不要用 curl 直抓详情页**：豆瓣反爬返回 131 字节拦截页，白费时间。
5. 连续抓取多部之间间隔几秒，降低限流概率。

抓取完整信息（导演、类型、制片国家/地区、年份、评分、一句话简介）后进入第 3 步；否则只写电影名/链接/提取码，备注"豆瓣信息待补全"，不编造。

### 3. 备注规范

- **只写豆瓣简介**：剧情梗概（100 字内）、来源标注（如"信息来自搜索，未核对豆瓣"）
- **禁止塞片源信息**：1080P / 4K / 中字 / 多国字幕 / 蓝光原盘 / 夸克链接描述等全部剥离——表格里已经单独有"网盘链接/提取码"两列承载资源信息，备注是纯内容区，重复塞没意义还丑
- 脚本 `append_movie.py` 已内置 `strip_source_tags()` 兜底清洗，即使传入不干净的字符串也会自动过滤

### 3. 查重与写入

用脚本一次性写入整批（脚本内置查重，重复电影名会跳过并在结果中报告）：

```bash
"C:/Users/zhen/.workbuddy/binaries/python/envs/default/Scripts/python.exe" \
  "C:/Users/zhen/.workbuddy/skills/douban-movie-collector/scripts/append_movie.py" \
  --xlsx "<表格绝对路径>" \
  --json '[{"name":"肖申克的救赎","link":"https://pan.xxx.com/s/xxxx","code":"abcd","country":"美国","year":1994,"genre":"剧情/犯罪","director":"弗兰克·德拉邦特","rating":9.7,"remark":"简介一句话"}]'
```

脚本行为（无需再校验）：

- 序号在现有最大值上顺延；观看状态默认「想看」；收藏日期默认今天
- 样式从上一数据行复制，日期列强制 yyyy-mm-dd
- 按电影名查重（忽略空白/书名号/大小写），命中即跳过；确要重复录入时加 `--force`
- 文件被占用（预览开着）时自动改存 `<原名>_new.xlsx`，输出 `"status":"LOCKED"` —— 此时告知用户关闭预览后，把 `_new.xlsx` 覆盖回原名（mv）再删除确认

### 4. 回报

向用户汇报一张小表：每部电影的 写入行号 / 评分 / 导演 / 类型，以及 跳过原因（重复/抓取失败）。
抓取信息附豆瓣条目链接；搜索兜底的数据注明来源和获取日期。

## 边界

- 不编造评分、导演、年份——抓不到就留空并说明
- 不修改现有数据行，只追加
- 写入前不必逐条问用户确认；只有「多条候选命中」和「全表找不到目标 xlsx」时才开口问
- **样式跟随现有表格**：append 脚本从上一数据行复制样式，改表格配色/列宽后无需改 skill

## 数据验证

- 评分数据来源：豆瓣 suggest 接口→详情页（若返回）→ WebSearch 兜底（多源交叉验证）
- ⚠️ 豆瓣详情页评分可能因 JS 渲染为空，curl 直抓会被反爬拦截（返回131字节），此时用 WebSearch 多源验证（百度百科+搜狐+影视站等）
- 写入后用户可要求核对，脚本本身无法自动校验，需手动 WebSearch 多源对比
- 多源一致才采信，单一来源不可信时备注"评分来自单源搜索，建议核实"
