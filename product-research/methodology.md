# 产品调研方法论

## 核心理念

**多源交叉验证 + 浏览器实测 + 深度调研**

不依赖单一来源，不轻信官方宣传，用事实和数据说话。

## 完整流程

### Phase 1: 需求澄清

1. **确定输出类型**
   - 调研报告 / 评测文章 / 技术文档 / 对比分析
   - 选择对应模板

2. **明确调研范围**
   - 关注哪些维度（功能、定价、技术、市场）
   - 时间范围（最新版本 vs 历史演进）
   - 深度要求（简报 vs 深度报告）

3. **确认交付标准**
   - 文件命名规范
   - 来源标注要求
   - 数据验证标准

### Phase 2: 素材收集

#### 2.1 官方素材

- 官网首页、产品页、定价页
- 官方文档、使用指南
- 官方博客、更新日志

**抓取方式**：`baoyu-url-to-markdown`

#### 2.2 第三方评测

- 专业媒体评测（36kr、极客公园）
- 用户社区评测（知乎、V2EX）
- YouTube/B站评测视频（转录为文字）

**目标**：5-10 个来源，覆盖不同视角

#### 2.3 浏览器实测

**为什么需要**：
- 验证文章描述是否准确
- 获取真实 UI 结构和功能入口
- 发现文章未提及的细节

**操作步骤**：
1. 打开官网，截图关键页面
2. Snapshot 提取页面结构
3. 测试核心功能流程
4. 记录实际体验

#### 2.4 深度调研

**补充搜索**：
- 定价方案（可能有隐藏优惠）
- 技术架构（GitHub、技术博客）
- 竞品信息（市场份额、用户评价）
- 融资背景（公司发展阶段）
- 行业事件（涨价、用户迁移等）

**工具**：`WebSearch`、`WebFetch`

### Phase 3: 报告生成

1. **加载模板**
   - 根据场景选择对应模板
   - 复制模板结构

2. **填充内容**
   - 按章节逐一填充
   - 标注数据来源
   - 遇到不确定的信息标记 ⚠️

3. **生成初稿**
   - 先完成框架
   - 再补充细节
   - 保留优化空间

### Phase 4: 逐章审查

**审查原则**：
- 每章内容必须有来源支撑
- 关键数据至少 2 个来源交叉验证
- 不确定的信息明确标注

**审查步骤**：
1. 通读每章内容
2. 对照原始素材验证
3. 替换 ⚠️ 占位符
4. 补充缺失信息
5. 优化表达方式

### Phase 5: 质量检查

**检查清单**：
- [ ] 所有章节都有实质内容
- [ ] 所有数据标注来源
- [ ] 关键数据交叉验证
- [ ] 无 ⚠️ 占位符
- [ ] 文件命名符合规范
- [ ] 素材归档到 workspace

## 关键原则

### 1. 多源交叉验证

**为什么**：
- 单一来源可能有偏见或错误
- 官方宣传可能夸大
- 第三方评测可能有利益关系

**怎么做**：
- 同一事实至少 2 个来源确认
- 优先选择独立第三方来源
- 标注来源可信度

### 2. 浏览器验证

**为什么**：
- 文章可能过时
- 描述可能与实际不符
- 需要真实 UI 结构

**怎么做**：
- 打开官网，实际体验
- 截图关键页面
- 记录功能入口

### 3. 深度调研

**为什么**：
- 已有素材可能不完整
- 需要补充定价、技术、竞品等维度
- 需要发现行业事件和趋势

**怎么做**：
- 主动搜索关键信息
- 查看 GitHub、融资新闻
- 关注行业动态

### 4. 逐章迭代

**为什么**：
- 一次性生成质量不稳定
- 需要逐步验证和优化
- 保留改进空间

**怎么做**：
- 先生成框架
- 再逐章审查升级
- 反复迭代到满意

## 常见问题

### Q: 素材不够怎么办？

A: 
1. 扩大搜索范围（英文搜索、海外媒体）
2. 主动联系产品方（如果有渠道）
3. 降低深度要求（改为简报）

### Q: 信息来源冲突怎么办？

A:
1. 优先选择官方来源
2. 优先选择独立第三方
3. 标注冲突，让读者自行判断

### Q: 报告写得太长怎么办？

A:
1. 考虑改为简报版本
2. 拆分为多个专题报告
3. 删除非核心内容

### Q: 如何保证报告时效性？

A:
1. 标注调研日期
2. 标注数据来源日期
3. 建立更新机制（每季度检查）

## 案例参考

### 案例 1: LibTV 调研报告

**素材来源**：9 个
- 官网 + 官方文档
- GitHub 仓库
- 知乎评测 x2
- 搜狐评测
- BestBlogs 评测
- Dreamina 评测（竞品）
- Pexo 评测（竞品）

**深度调研**：
- WebSearch 补充定价、融资、技术架构
- Playwright 打开官网验证 UI

**迭代过程**：
1. 生成 11 章框架
2. 逐章审查，替换占位符
3. 补充使用方式章节（浏览器实测）
4. 补充定价章节（WebSearch）
5. 补充技术架构（深度调研）

**最终输出**：1000+ 行完整报告

### 案例 2: 即梦 AI 调研报告

**特点**：
- 竞品对比（与 LibTV）
- 涨价事件分析
- 用户迁移效应

**关键发现**：
- 即梦连续 3 次涨价
- 大量用户转向 LibTV
- "便宜不排队"成为核心卖点

## 持续改进

### 方法论迭代

每次调研后总结：
- 哪些步骤有效
- 哪些步骤可以优化
- 新的工具或来源

### 模板优化

根据使用反馈：
- 调整章节结构
- 增删维度
- 优化表达方式

### 工具链升级

关注新工具：
- 更高效的抓取工具
- 更好的浏览器自动化
- 更智能的搜索工具
