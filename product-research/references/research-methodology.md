# 深度调研方法论

参考 deep-research V8，适配产品调研场景。核心思路：**先计划、再笔记、后综合**，不是一股脑搜完就写。

---

## 1. 研究计划（搜索前先写）

每次深度调研前，先写一个简短计划，避免盲目搜索。

### 模板

```markdown
## 研究计划

### 调研目标
- 需要回答的核心问题（1-3 个）

### 已知信息
- 已有素材覆盖了什么

### 信息缺口
| 缺口 | 搜索关键词 | 目标来源类型 | "完成"标志 |
|------|-----------|-------------|-----------|
| 定价方案不全 | `{product} pricing 2024` | 官方/评测 | 找到完整价格表 |
| 技术架构不清楚 | `{product} architecture` | 技术博客/GitHub | 理解核心组件 |
| ... | ... | ... | ... |

### 什么证据会改变结论
- 如果 {X}，则需要修正 {Y}
```

### 何时需要计划

| 场景 | 是否需要计划 |
|------|-------------|
| 用户给了明确 URL，只需抓取 | 不需要 |
| 简报/速览 | 不需要 |
| 完整调研报告 | 需要 |
| 竞品对比/行业分析 | 需要 |

## 2. 结构化笔记（每次搜索生成）

每个调研线程生成一份笔记，分离**事实、分析、缺口、冲突**。

### 笔记模板

```markdown
## 调研线程：{主题}

### 来源
[1] 标题 | URL | 评分 | 类型 | 日期
[2] 标题 | URL | 评分 | 类型 | 日期

### 事实（仅来自来源）
- 具体事实 1 [1]
- 具体事实 2 [2]

### 分析（你的综合判断）
- 这些事实意味着什么 [1][2]
- 哪些数据被夸大/低估/不确定

### 关键论断支撑
- 论断：{重要结论}
  来源：[2]
  支撑：{来源说了什么，1-2 句}

### 冲突 / 未解决
- 来源 [1] 和 [3] 在 {X} 上矛盾
- 原因：{为什么矛盾}

### 缺口
- 搜了但没找到的信息
- 什么证据最能降低不确定性
```

### 规则

**事实部分**：
- 只写来源里有的
- 一条一个 bullet，标注来源编号
- 不写"很多人认为"这种模糊表述

**分析部分**：
- 和你的综合判断分开
- 可以推断，但要标明是你的推断

**缺口部分**：
- 诚实标注
- 缺口不是失败，隐藏的缺口才是

## 3. 来源评分（简化 4 维）

对每个来源打 4 个分（1-10），快速判断可信度。

| 维度 | 含义 | 评分标准 |
|------|------|---------|
| **权威性 (Aut)** | 来源是否可靠 | 官方=9-10, 专业媒体=7-8, 个人博客=4-6, 匿名=1-3 |
| **时效性 (Rec)** | 信息是否最新 | 3 个月内=9-10, 1 年内=7-8, 1-2 年=5-6, 2 年以上=3-4 |
| **相关性 (Rel)** | 和调研目标的匹配度 | 直接相关=9-10, 部分相关=6-8, 间接=3-5 |
| **独立性 (Dep)** | 是否有利益关系 | 独立第三方=9-10, 有合作但标注=6-8, 官方自说=5, 未标注利益=1-4 |

### 综合分

```
综合 = (Aut + Rec + Rel + Dep) / 4
```

### 使用方式

- **核心数据**（定价、用户数、融资）：需要综合分 ≥ 7 的来源
- **辅助信息**（功能描述、使用体验）：综合分 ≥ 5 即可
- **冲突裁决**：优先采用综合分高的来源

### 示例

```
[1] LibTV 官网定价页 | https://... | Aut:10 Rec:9 Rel:10 Dep:5 = 8.5 | 官方 | 2024-12
[2] 知乎评测 | https://... | Aut:6 Rec:8 Rel:9 Dep:9 = 8.0 | 独立第三方 | 2024-11
[3] 搜狐转载 | https://... | Aut:5 Rec:6 Rel:7 Dep:6 = 6.0 | 媒体转载 | 2024-08
```

## 4. 冲突处理规则

来源冲突时的处理优先级：

### 优先级

1. **官方来源** > 第三方来源（官方数据优先，但要注意官方可能夸大）
2. **独立第三方** > 有利益关系的来源（独立评测更可信）
3. **新来源** > 旧来源（时效性优先）
4. **高评分来源** > 低评分来源（综合分优先）

### 处理方式

| 冲突类型 | 处理方式 |
|---------|---------|
| 数字冲突（价格、用户数） | 采用官方来源，标注第三方数据差异 |
| 功能描述冲突 | 浏览器实测验证，标注"实测确认" |
| 评价冲突（好评 vs 差评） | 保留双方观点，标注来源立场 |
| 时间冲突（上线时间等） | 采用最早发布的官方来源 |

### 标注格式

```markdown
- 定价：¥99/月（来源：官网 [1]）
  > ⚠️ 知乎评测显示为 ¥129/月 [2]，可能存在版本差异
```

## 5. 缺口驱动搜索

不是盲目搜，而是**读完已有资料后识别缺口再定向搜索**。

### 流程

1. **读完已有素材**
2. **逐章检查模板**，标记缺失维度
3. **生成缺口清单**
4. **按优先级搜索**（核心维度优先）
5. **验证搜索到的信息**（交叉验证）

### 常见缺口维度

| 维度 | 缺口信号 | 搜索关键词 |
|------|---------|-----------|
| 产品概述 | 不知道公司背景、上线时间 | `{product} 公司 成立时间` |
| 核心功能 | 功能列表不完整 | `{product} features list` |
| 定价方案 | 没有完整价格表 | `{product} pricing plans` |
| 技术架构 | 不知道技术栈 | `{product} tech stack architecture` |
| 竞品信息 | 不知道主要竞品 | `{product} alternatives competitors` |
| 用户评价 | 没有真实用户反馈 | `{product} user reviews` |
| 融资背景 | 不知道发展阶段 | `{company} funding series` |

## 6. 调研执行流程

### 完整流程

```
1. 写研究计划（明确缺口和目标）
   ↓
2. 按缺口搜索（每个缺口 2-3 个来源）
   ↓
3. 生成结构化笔记（事实/分析/缺口/冲突）
   ↓
4. 来源评分（4 维评分）
   ↓
5. 冲突处理（按优先级规则）
   ↓
6. 综合写入报告（标注来源）
   ↓
7. 质量自检（对照质量门控）
```

### 简化流程（简报/速览）

```
1. 搜索关键信息（3-5 个来源）
   ↓
2. 快速验证（交叉检查核心数据）
   ↓
3. 写入简报（标注来源）
```
