# 质量门控

简化版质量自检，参考 deep-research V8，适配产品调研场景。输出前必须过一遍。

---

## 门控 0：路由正确性

**检查：这个任务真的需要完整调研吗？**

| 通过 | 失败 |
|------|------|
| 确实需要多源综合 | 只是简单查询（用 WebSearch 直接回答即可） |
| 用户要报告/文章 | 用户只想要一句话答案 |
| 输出类型匹配需求 | 生成了完整报告但其实简报就够了 |

**失败时怎么办**：下次触发时选更轻量的输出类型。

---

## 门控 1：过程完整性

**检查：调研过程有迹可循吗？**

### 必需产物

| 产物 | 简报 | 完整报告 | 竞品/行业分析 |
|------|:---:|:------:|:----------:|
| 研究计划 | - | ✓ | ✓ |
| 调研笔记 | - | ✓ | ✓ |
| 来源清单（含评分） | ✓ | ✓ | ✓ |
| 最终报告 | ✓ | ✓ | ✓ |

### 检查项

- [ ] 目标写下来了（不是脑子里想想）
- [ ] 关键信息有笔记可追溯
- [ ] 缺口和冲突已明确标注
- [ ] 核心论断有来源支撑

### 失败时怎么办

- 补写笔记（从实际使用的来源回溯）
- 补充缺口搜索
- 为核心论断补充支撑

---

## 门控 2：来源与引用完整性

**检查：引用可靠吗？**

### 硬伤（必须修正）

- ❌ 引用了不存在的来源（编造 URL）
- ❌ 核心数据无来源（定价、用户数、融资等）
- ❌ 引用已删除的来源
- ❌ 法律/财务/安全相关表述无支撑

### 检查项

- [ ] 每个核心事实都有对应来源
- [ ] 来源编号能正确对应
- [ ] 冲突数据已标注，不是隐藏
- [ ] 来源强度匹配论断强度（重大结论用高评分来源）

### 失败时怎么办

- 删除弱引用或悬空引用
- 降低置信度标注
- 重新查找支撑

---

## 门控 3：输出质量

**检查：用户看到的东西好吗？**

### 所有输出必须

- [ ] 直接回答了用户的问题
- [ ] 有明确的局限性和不确定性说明
- [ ] 来源支撑的内容和综合分析分开
- [ ] 不确定性程度与证据质量匹配

### 按输出类型额外检查

**简报**：
- [ ] 简洁，不啰嗦
- [ ] 核心信息在前

**完整报告**：
- [ ] 覆盖度足够
- [ ] 章节逻辑连贯
- [ ] 来源质量经得起推敲

**竞品/行业分析**：
- [ ] 对比维度一致
- [ ] 数据来源可追溯
- [ ] 结论有依据

### 失败时怎么办

- 删掉通用废话
- 补充缺失的局限性说明
- 用有用的细节替换空洞表述

---

## 门控 4：效率

**检查：有没有浪费？**

### 监控指标

- 搜索次数
- 抓取次数
- 报告长度 vs 请求类型
- 重复搜索次数

### 警告信号

- ⚠️ 简报写了 2000 字
- ⚠️ 同一个信息搜了 3 遍
- ⚠️ 抓取了已经有的来源
- ⚠️ 搜索没有目标的关键词

### 失败时怎么办

- 下次选更轻量的模式
- 搜索前先列关键词，避免发散
- 抓取前检查是否已有

---

## 快速自检清单

输出前 30 秒过一遍：

```
□ 核心数据都有来源吗？
□ 关键数据交叉验证了吗？（至少 2 个来源）
□ 冲突数据标注了吗？
□ 有局限性说明吗？
□ 来源评分 ≥ 7 吗？（核心数据）
□ 文件命名对吗？
□ 素材归档了吗？
```

**全部通过** → 可以输出  
**有未通过项** → 先修正再输出
