# 报告更新工作流

## 更新时机

### 定期更新
- **建议周期**：每季度检查一次
- **触发条件**：报告日期超过 3 个月

### 事件驱动更新
- 产品重大版本更新
- 定价方案调整
- 公司融资/并购
- 行业重大事件
- 用户反馈发现错误

## 更新流程

### 1. 评估更新范围

#### 小范围更新
**适用场景**：
- 个别数据更新
- 小功能调整
- 价格变动

**操作**：
- 直接修改原文件
- 在文件开头标注更新日期
- 记录变更内容

#### 中范围更新
**适用场景**：
- 多个章节需要更新
- 新增重要功能
- 竞品格局变化

**操作**：
- 创建新版本文件：`{product}-research-report-v2.md`
- 保留旧版本作为历史参考
- 完整记录变更内容

#### 大范围更新
**适用场景**：
- 产品定位重大调整
- 行业格局根本性变化
- 原报告结构不适用

**操作**：
- 重新调研
- 创建全新报告
- 旧报告归档

### 2. 搜索最新动态

#### 信息来源
1. **官方网站**
   - 产品更新日志
   - 定价页面
   - 功能介绍

2. **新闻报道**
   - 融资新闻
   - 产品发布
   - 行业分析

3. **社交媒体**
   - 官方账号
   - 用户讨论
   - 评测文章

4. **社区反馈**
   - GitHub issues
   - 用户论坛
   - 评价网站

#### 搜索关键词
```
{product name} update {year}
{product name} new features
{product name} pricing change
{product name} funding
{product name} vs competitors
```

### 3. 对比分析

#### 创建变更清单

```markdown
## 变更清单

### 新增内容
- [ ] 新功能 A
- [ ] 新定价方案

### 修改内容
- [ ] 用户数：100万 → 200万
- [ ] 价格：¥99 → ¥129

### 删除内容
- [ ] 已废弃功能 B

### 需要验证
- [ ] 技术参数是否更新
- [ ] 竞品信息是否需要调整
```

### 4. 执行更新

#### 小范围更新

```bash
# 直接编辑原文件
vim {product}-research-report.md

# 在文件开头添加更新记录
> 最后更新：{YYYY-MM-DD}
> 更新内容：
> - 更新了定价方案
> - 补充了最新用户数据
```

#### 中范围更新

```bash
# 复制为新版本
cp {product}-research-report.md {product}-research-report-v2.md

# 编辑新版本
vim {product}-research-report-v2.md

# 在文件开头添加版本说明
> 版本：v2.0
> 更新日期：{YYYY-MM-DD}
> 主要变更：
> - 新增第三章"使用方式"
> - 更新了竞品对比
> - 补充了技术架构细节
```

### 5. 验证更新

#### 检查清单
- [ ] 所有新增内容有来源支撑
- [ ] 更新的数据经过交叉验证
- [ ] 新旧版本差异明确标注
- [ ] 链接有效性检查
- [ ] 格式规范检查

#### 质量检查
使用 `standards/quality-checklist.md` 进行全面检查。

### 6. 归档旧版本

#### 归档策略

**保留历史版本**：
```
{product}-research-report-v1.md  # 第一版
{product}-research-report-v2.md  # 第二版（当前）
```

**创建变更日志**：
```markdown
# {product} 报告变更日志

## v2.0 ({YYYY-MM-DD})
### 主要变更
- 新增功能 X 介绍
- 更新定价方案
- 补充竞品对比

### 数据来源
- 新增 3 个来源
- 更新 5 个来源

## v1.0 ({YYYY-MM-DD})
- 初始版本
```

## 版本命名规范

### 版本号规则

- **v1.0**：初始版本
- **v1.1**：小范围更新（数据更新、小幅调整）
- **v2.0**：中范围更新（新增章节、结构调整）
- **v3.0**：大范围更新（全面重写）

### 文件名规范

```
{product}-research-report.md       # 当前版本（最新）
{product}-research-report-v1.md    # 历史版本
{product}-research-report-v2.md    # 历史版本
```

或者使用时间戳：

```
{product}-research-report-{YYYYMMDD}.md
```

## 自动化更新提示

### 使用 Cron 定期提醒

```bash
# 每季度检查一次
0 0 1 */3 * echo "检查产品报告更新" | mail -s "报告更新提醒" user@example.com
```

### 使用日历提醒

创建日历事件：
- **标题**：检查 {product} 报告更新
- **周期**：每季度
- **提醒**：检查报告日期，搜索最新动态

## 最佳实践

1. **及时更新**：发现重大变化立即更新
2. **版本管理**：保留历史版本，便于对比
3. **变更记录**：详细记录每次更新内容
4. **来源追溯**：更新内容标注新来源
5. **质量把控**：更新后重新做质量检查

## 常见问题

### Q: 更新后发现旧版本有错误怎么办？

A: 
- 如果错误影响重大，发布修正版本
- 在变更日志中说明修正内容
- 考虑是否需要通知使用者

### Q: 多个产品报告需要更新，如何安排优先级？

A: 
1. 用户最多的产品
2. 变化最大的产品
3. 最近有决策需求的产品
4. 按更新时间排序

### Q: 更新后发现信息不准确怎么办？

A: 
- 立即修正并标注
- 追溯错误来源
- 在变更日志中说明
- 加强来源验证

### Q: 如何判断是否需要更新？

A: 
- 报告日期超过 3 个月
- 产品有重大更新
- 行业有重大变化
- 用户反馈问题
- 决策需要最新信息
