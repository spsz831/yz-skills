# 项目级 AGENTS.md

1. 适用范围

- 仅适用于 `E:\WorkCodex\szxs-gzh`
- 这里记录本项目的稳定流程与验证要求
- 用户的即时指令优先于本文件

2. `szxs-gzh` 日更流程

- 生成 51 万年历相关内容时，先用 `Playwright` 打开当天页面核对，再写初稿
- 51 页面日期参数固定使用 `STIME=YYYY-MM-DD`
- 不要用静态源码、旧缓存、bundle 痕迹代替当天页面验证
- 若目标日期遇到中国传统节日、二十四节气或需要点出的特殊节日，需在文章最前面的**阳历日期**一栏追加该节日信息；只加在第一行日期里，不加到干支日期行
- 若同一天有多个节日/节气，按“传统节日 / 二十四节气 / 其他特殊节日”顺序并列追加，保持简洁，不写成长解释
- 节日信息默认处理优先级：传统节日 > 二十四节气 > 特殊节日；若同天信息过多，正文与播客都优先突出前两类
- 电影部分按文章日期往前推 10 天去核对 `cikeee` 当前页面
- 电影标题、年份、台词、图片 URL 要一起核对，不能只改其中一项

3. 生肖与版式

- 生肖正文顺序以用户导出的校正稿为准
- 顶部摘要、正文顺序、需要注意的生肖三处必须一起同步
- `szxs-gzh` 示例里的 diff 标记和段首格式属于模板规则，不能随意改写
- 遇到 `+ / -`、`每日宜忌`、`避讳方位` 等样式问题，先对照示例再改
- 文章里的 12 生肖正文允许固定骨架，但不允许连续多天复用同一批起手句、判断句和安慰句
- 特别避免高频重复这类文章句路：`今天整体不错/不差/偏稳`、`适合推进/协调/补漏洞`、`很多事情会慢慢顺开`、`别太急，稳一点更好`、`先把节奏稳住`
- 同样是高位生肖，也要区分重心，不要每天都写成同一种“贵人 + 机会 + 稳住”套路；可分别偏向执行、财运、人际、情绪、感情或决断力
- 播客稿的标题备选必须按固定 5 种格式输出，不要自由改成别的标题体
- 播客标题备选的第 1 条不能长期重复 `愿X，诸事有序` 这一类同构句；必须从当天 `建星 / 宜忌 / 方位提醒 / 节奏提醒` 里抽真实钩子做变化
- 标题第 2 到第 5 条虽然格式固定，但内部重心必须主动拉开：
  - 第 2 条不必总是“建星 + 宜X忌Y”，可在“主卡宜 / 主卡忌 / 当天节奏判断”之间轮换
  - 第 3 条不必总写成“属X迎好运，属Y属Z紧随其后”，可在不改变生肖型前提下轮换“领跑 / 靠前 / 回暖 / 上行”表达
  - 第 4 条不必总是“先……再……”，可轮换成判断型、对照型或单句能量型
  - 第 5 条不必总是“宜先X，把Y稳住的一天”，可轮换成极简单句、节奏判断句、留白型提醒句
- 标题 2 到 5 条不能长期围着同一组词打转，尤其避免连续多日反复使用：`稳、收、守、顺、节奏、分寸`
- 若当天有中国传统节日、二十四节气或特殊节日，播客开场必须自然提到，并补一句贴合当天气质的祝福、提醒或简短知识点；篇幅要短，不能喧宾夺主
- 节日 / 节气在播客中的表达要按类型区分：传统节日偏祝福与人情提醒，节气偏时令气质与身心提醒，特殊节日偏现实问候或轻知识点
- 节日 / 节气开场说明控制在 1 到 3 句；默认不讲起源、不长篇解释、不做专题展开
- 节日/节气信息原则上在播客开场完成，不在电影收尾段重复展开；电影段最多只允许轻轻回扣当天节日气质，不能写成节日专题
- 播客允许固定骨架，但不允许固定句路；最近几天已用过的提问句、转场句、总结句，后续生成时应主动换写，避免连续多天听感相同
- 特别避免连续复用这类承接句：`那先看生肖`、`这一组很明显`、`那明天更要留神的三位呢`、`把明天的宜忌再直接报一遍吧`、`我听下来`
- 四知在播客里应少用“报表式栏目句”，多用“先判断、再解释”的说法；例如少直接说“明天的次吉是……”，多改成“接下来这几位，明天也都有上行空间”
- 电影收尾段不能连续多天使用同一种“放在明天看，也像个提醒 / 愿大家明天……”句路；要轮换收束方式，避免每期都像同一结尾模板

4. 验证要求

- 任何“已核对 51 / cikeee”的说法，都要先有实际浏览器验证
- 不确定时优先标注为待核对，不要把推断写成事实
- 定稿前至少复核一次：生肖顺序、建星、宜忌、方位、电影信息、收尾句
- 若当天有节日/节气，复核其是否只出现在阳历日期行，以及播客开场是否已正确提及
- 生成文章或播客前，优先快速扫最近 7 天同类型稿件，检查高频重复的起手句、承接句、总结句、标题钩子是否又出现
- 若发现明显重复，不要求推翻整稿，但应至少改掉最突出的 2 到 4 处模板句
