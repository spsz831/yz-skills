# x-spsz：X 中文深度解读卡片

## 目标

把用户提供的素材转成一套可发布内容：

1. 一张中文深度解读卡片的文字方案；
2. 一段不重复卡片正文的 X 配套推文；
3. 按需生成图片、完整 Prompt，或审核用户提供的成图。

这不是纯文字海报、空白模板、壁纸，也不是无观点的资讯搬运。默认优先做“好看的彩色插画卡片”，不要把整张图排成密集文字页。

## 调用模式

根据用户意图选择模式；未指定时默认 `generate`，当前环境无法生图时降级为 `prompt`。

- `draft`：只输出卡片文案和配套推文。
- `prompt`：输出可复制的完整生图 Prompt，不调用生图工具。
- `generate`：生成卡片图片；优先使用当前可用的图像生成能力，不虚构模型、分辨率或已完成的生成操作。
- `review`：检查用户提供的成图，重点检查文字、版式、事实、落款和可读性。

## 素材与事实核验

涉及新闻、政策、人物近期言论、公司数据、价格、产品规格或其他时效性信息时：

1. 先判断是否需要联网核验；需要时使用当前可用的联网技能和可靠来源。
2. 区分“已确认事实”“来源转述”“作者判断”和“推测”。
3. 不补写素材中没有依据的数字、日期、因果关系和引语。
4. 无法确认的内容使用“据报道”“截至目前”“可能”等准确措辞。
5. 每个事件必须绑定一个具体日期，统一写成 `YYYY年M月D日`，例如 `2026年9月10日`；禁止只写“2026年9月”“近日”或“今天”。
6. 区分事件发生日、官方发布日期、人物评论日和文章发布日期；卡片眉题优先使用事件发生日或官方发布日期，不能用当前日期代替事件日期。
7. 多日事件使用日期范围，例如 `2026年9月10日—9月14日`；只有月份而没有日的素材不能直接做终稿，应先核验或标记“具体日期待核实”。
8. 输出简短的“事实核验”区；用户只要成品时可折叠为一句说明。
9. 保留来源链接或来源名称，除非用户明确要求不展示。

## 先选卡片模式

### 标准卡

适用于单条新闻、单个观点或一个明确事件。固定 6 段：

0. 顶部主题插图
1. 眉题与具体日期
2. 主标题
3. 正文区块，最多 3 段
4. 自写收束金句
5. `@spsz0831`

总文字量控制在 60–90 个中文字符左右；主标题不超过 10 字；金句不超过 14 字；正文每段不超过 20 字。字符统计以可见中文、数字和英文为主，标点不作为扩充字数的手段。

### 深度卡

适用于人物观点、时间线、数据对比和多来源材料。允许加入：

- 时代或主题眉题；
- 两个证据块或时间点；
- “我的判断”区块；
- 收束金句与落款。

深度卡不强行套用标准卡的 60–90 字限制，但仍要短句化、分层清楚，避免把文章全文塞进图片。原文引用、意译和作者判断必须明确区分。

## 固定内容约束

- 主标题必须重写，有反差、比较或视角钩子，不能直接复制素材原句。
- 收束金句必须自写，不冒充人物原话，不使用空泛鸡汤。
- 卡片底部只放 `@spsz0831`，不添加 slogan、“一家之言”“个人整理”等文字。
- 眉题必须包含具体事件日期，格式为 `主题 · YYYY年M月D日`；不使用“今天”“近日”或只有年月的模糊时间词。
- 中文标点统一使用全角标点：，。、：；“”「」——。
- 推文控制在 100 字以内，补充观点、背景或问题，不照搬卡片正文。
- 不把未发生的计划写成已经完成，不把推测写成事实。

## 视觉规范：插画主导

默认使用 3:4 竖版彩色插画卡片，插图优先、文字辅助：

- 主题插画占画面约 55–65%，不再限制为顶部小配图；
- 插画要有明确主体、前中后景、空间层次、光影、材质和颜色变化；
- 默认使用彩色编辑插画、叙事插画、电影感场景或精致 3D 概念插画；根据素材选择最合适的风格；
- 色彩要丰富但不脏乱，避免单色、灰度、空白背景、廉价渐变、随机图标和 emoji；
- 颜色根据主题动态选择，不强制所有主题使用米白底；科技可用蓝紫、青色和电光色，地缘与历史可用红、金、靛蓝，人物与生活主题可用暖色和自然色；
- 文字区约占 35–45%，只保留标题、少量要点、金句和落款；长解释放进配套推文，不塞进图片；
- 文字区可以使用半透明色块、纸张质感、渐变暗部或留白区域承托文字，但不能压住插画主体；
- 插画与文字区要有自然过渡，不要像“上面一张图、下面一块白板”简单拼接；
- 不在主题插画内部生成无关文字、假 Logo、假 UI、乱码或装饰性字母；
- 中文字体优先思源宋体 / Noto Serif SC 与思源黑体 / Noto Sans SC。

工具不支持某个精确尺寸或格式时，使用工具实际支持的最佳选项，并如实说明；不要声称已经输出 4K、PNG 或某个指定模型，除非工具结果能够确认。

## 输出格式

除非用户另有要求，按以下顺序输出：

```text
【模式】标准卡 / 深度卡；draft / prompt / generate / review
【事实核验】事件日期、已确认事实、待确认内容、来源
【主题插图】主体、场景、前后景、色彩、光影和视觉隐喻
【眉题】...
【主标题】...
【正文】...
【收束金句】...
【@ID】@spsz0831
【配套推文】...
【自检结果】字数、事实、格式和风险
```

使用 `prompt` 时，在上述内容后附上完整生图 Prompt。使用 `generate` 时，直接生成图片并同时给出精简版文案与自检结果。使用 `review` 时，指出问题、严重程度和最小修改建议。

## 执行流程

1. 判断用户要 `draft`、`prompt`、`generate` 还是 `review`。
2. 判断素材属于标准卡还是深度卡。
3. 对时效性事实进行核验，建立事实与观点边界。
4. 生成插画优先的主题描述、标题、少量正文、金句和推文；先把具体事件日期写入眉题。
5. 读取 `checklist.md`，完成内容侧自检。
6. `prompt` 模式读取 `prompt-template.md`，只填充一次，不重复拼接前缀。
7. `generate` 模式调用当前可用图像能力；不支持时降级为 `prompt`。
8. 用户提供成图后，按图侧清单审核；发现文字错误时优先建议重新生成或局部修正。
9. 遇到新的失败模式，更新检查清单或案例，不随意增加固定规则。
