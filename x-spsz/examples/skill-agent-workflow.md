# 案例：Skill → AI Agent → 任务结果

## 适用内容

个人 AI 工作流、Skill 使用经验、Agent 调度和规则管理复盘。

## 内容结构

- 经验背景：半年多实践，积累 100 多个 Skills；
- 核心判断：问题不在数量，而在是否给任务加载了正确规则；
- 四个结论：删除规则不等于变强、错误规则更危险、私有约定要保留、抽象和低频规则要简化；
- 收束观点：先选对，再验证。

## 配图结构

使用清晰横向流程：

`Skill 模块 → AI Agent → 任务结果`

左侧用 3–4 个不同色块表示能力模块，中间用一个明确的 Agent 工作中枢表示调度，右侧用一张任务结果卡表示输出。关系清楚优先于复杂装饰。

## 配套推文示例

我搭建并使用这套 AI Skill 工作流已经半年多，积累了100多个 Skills。后来发现，问题不是规则越多越好，而是有没有给当前任务加载正确的规则。该保留个人约定和硬性要求，删掉过时规则，简化空话。Skill 要少而准，先选对，再验证。

## 避免

- 不使用蓝紫霓虹、赛博城市、发光大脑等泛化 AI 视觉；
- 不把上方插图做成抽象球体或复杂插件面板；
- 不把四个结论压缩成无法理解的口号；
- 不为了装饰增加与 Skill、Agent、任务结果无关的元素。
