# HomeServer 垂类内容系统

## 五个固定栏目

### 1. HomeServer 入门

解释概念和选择：HomeServer、NAS、Homelab、Docker、Proxmox、虚拟机、容器、备份、远程访问。

### 2. 我的实践记录

使用固定结构：

```text
我想解决的问题 → 使用的设备/软件 → 实际过程 → 遇到的问题 → 最终效果 → 是否推荐
```

### 3. 一个工具解决一个问题

每篇只回答一个问题：

```text
工具是什么 → 它解决什么问题 → 谁适合用 → 使用门槛 → 我的判断
```

### 4. AI × HomeServer

优先做本地 AI、家庭自动化、AI 文件整理、AI 影视管理、AI 与 Home Assistant、AI 工作流部署，不把模型新闻孤立地搬过来。

### 5. 踩坑和复盘

使用固定结构：

```text
现象 → 原因 → 我怎么排查 → 最小解决方案 → 下次如何避免
```

## 周发布计划

默认每周三条：

- 周二：一个入门概念；
- 周四：一次个人实践或踩坑；
- 周六：一个工具、应用或 AI × HomeServer 主题。

当用户询问“今天发什么”时：

1. 读取近期发布记录（如果用户提供或工作区存在）；
2. 避免连续两次使用同一栏目；
3. 给出 1 个首选题和最多 2 个备选题；
4. 为首选题直接生成普通账号可发布的短文；
5. 说明配图是否必要，以及图片承担“解释关系、展示过程、营造氛围”中的哪一项。

## 选题模板

### 知识解释

```text
普通人问题：{读者真正想知道什么}
一句解释：{去掉术语后的答案}
一个例子：{真实使用场景}
结论：{读者下一步可以做什么}
```

### 实践记录

```text
日期：{具体日期}
目标：{想解决的问题}
设备/软件：{真实使用的东西}
结果：{成功、失败或仍待验证}
成本：{硬件、订阅、时间或电费}
建议：{适合谁，不适合谁}
```

### 工具推荐

```text
它是什么：{一句白话}
解决什么：{一个具体问题}
怎么开始：{最小步骤}
门槛：{费用、设备、技术要求}
我的判断：{推荐/谨慎推荐/不推荐}
```

### 踩坑复盘

```text
我遇到的现象：{具体问题}
真正原因：{已确认或待确认}
最小修复：{不扩写成复杂教程}
避免方法：{一条可执行建议}
```

## 账号复盘指标

不要只看曝光，优先记录：

- 收藏：内容是否有长期价值；
- 回复：是否引发真实问题；
- 主页访问：定位是否让人想继续了解；
- 新增关注：是否形成垂直认知；
- 重复率：是否连续发布相同角度。

每月只保留三项结论：表现最好的栏目、最常被追问的问题、下月应减少的内容。

## 双平台发布

每个可发布选题默认形成一个内容包：

```text
同一核心判断 → X 短版 → Threads 口语版 → 一张共用配图 → Alt Text → 发布后复盘
```

优先顺序：先写 X 版确定核心判断，再把真实场景和个人体会扩展到 Threads；不要先写长文再硬压缩成 X 版。
